读书笔记 Web安全深度解析

发表于 2020-04-20 更新于 2026-08-02 分类于 学习
本文字数： 2.1k 阅读时长 ≈ 2 分钟

💡 所有Web漏洞有一个共同根因：不可信输入未经校验到达了敏感操作。防御的核心原则只有一条——永远不信任输入。

Web安全的底层逻辑

Web安全看起来漏洞类型繁多：SQL注入、XSS、CSRF、文件上传、命令执行……但如果你退后一步看，所有漏洞遵循同一个模式：

用户输入 → 未经校验 → 到达敏感操作 → 漏洞

SQL注入：用户输入到达SQL执行器。XSS：用户输入到达HTML渲染。命令执行：用户输入到达系统命令。文件包含：用户输入到达文件路径。

防御只有一条原则：在输入和敏感操作之间，必须有校验层。 所有防御措施都是这条原则的具体实现。

核心漏洞类型

SQL注入：最经典的注入攻击

用户输入被拼接到SQL语句中执行。

攻击者输入 ' OR 1=1 --，SQL变成 SELECT * FROM users WHERE name='' OR 1=1 --'，绕过认证。

防御：

  • 预编译语句（参数化查询）：最根本的解决方案。输入永远是数据，不会被当作SQL语法。
  • 数据类型校验：数字型输入强制转int
  • 特殊字符转义：兜底方案，但不如预编译可靠

为什么预编译是终极方案：它从机制上保证了输入只能是数据，不是代码。这比任何过滤都可靠——你不需要预测攻击者会输入什么。

XSS跨站脚本：浏览器端的注入

恶意脚本被嵌入网页，在其他用户浏览器中执行。

三种类型：

  • 反射型：脚本在URL中，服务器直接返回到页面
  • 存储型：脚本存储在数据库（如评论区），所有访问者中招
  • DOM型：脚本不经过服务器，纯前端JS处理用户输入时触发

防御：

  • 输出编码：根据上下文（HTML/JS/CSS/URL）对特殊字符转义
  • HttpOnly Cookie：防止JS读取Cookie，阻断会话劫持
  • CSP（内容安全策略）：限制可执行脚本来源

文件上传漏洞：最容易被忽视

看起来无害的”上传图片”功能，可能是最危险的入口。

攻击思路：上传一个.php文件 disguised as图片，利用服务器解析漏洞执行它。

  • IIS解析漏洞：test.asp;.jpg被当作ASP执行
  • Apache解析漏洞：test.php.jpg从右往左解析，遇到php扩展名执行
  • PHP CGI解析漏洞：test.jpg/.php被当作PHP执行

防御：

  • 白名单校验扩展名（不要用黑名单——总有你没想到的）
  • 文件重命名（随机UUID，不要保留用户上传的文件名）
  • 存储到Web根目录外（用户不能直接通过URL访问）
  • MIME类型校验（但不能只靠MIME——可以被伪造）

命令执行漏洞

用户输入到达系统命令执行函数（如PHP的system()、exec()）。

攻击者输入 ; rm -rf /，系统执行了原命令后又执行了删除。

防御：避免使用系统执行命令。如果必须用，参数校验+转义+函数白名单。

CSRF：冒充用户身份

CSRF（跨站请求伪造）利用的是浏览器自动携带Cookie的机制。

用户在银行网站登录后，访问恶意网站。恶意网站发一个向银行转账的请求，浏览器自动带上银行Cookie——银行以为是用户本人操作。

与XSS的区别：XSS是注入脚本到受害者页面执行；CSRF是冒充受害者发请求。XSS不需要用户访问恶意网站，CSRF需要。

防御：

  • CSRF Token：每个请求带一个随机token，攻击者无法获取
  • SameSite Cookie属性：限制跨站Cookie发送
  • Referer校验：检查请求来源

安全测试的工具链

信息收集阶段

  • 搜索引擎site命令：site:example.com filetype:pdf 搜索敏感文件
  • Nmap：端口扫描，发现开放服务
  • DirBuster：目录爆破，发现隐藏路径

漏洞扫描阶段

  • Burp Suite：代理拦截+修改请求，Web安全测试瑞士军刀
  • AWVS/AppScan：自动化漏洞扫描
  • SQLMap：自动化SQL注入检测和利用

真正的安全测试思路

工具只是辅助。真正的安全测试是对抗性思维：

  1. 找到所有用户输入点（表单、URL参数、Header、Cookie、文件上传）
  2. 对每个输入点，问：如果我输入恶意数据，它会到达什么操作？
  3. 如果到达数据库→测SQL注入。到达HTML→测XSS。到达文件系统→测文件包含。到达命令行→测命令执行。

安全测试不是”用工具扫一遍”，是”像攻击者一样思考”。

防御哲学：纵深防御

单一防御措施总会被绕过。真正的安全是多层防御：

  • 第一层：输入校验（白名单 > 黑名单）
  • 第二层：参数化查询/输出编码（机制级防护）
  • 第三层：WAF（Web应用防火墙，拦截已知攻击模式）
  • 第四层：最小权限原则（数据库用户只给必要权限）
  • 第五层：日志监控+应急响应

没有任何一层是足够的。但每一层都能挡住一部分攻击，组合起来大幅提高攻击成本。

安全不是”绝对不被攻破”，而是”攻破的代价大于收益”。

✅ 总结

  • 所有Web漏洞共享同一根因：不可信输入未经校验到达敏感操作
  • 预编译语句从机制上消灭SQL注入——输入永远是数据不是代码
  • 安全测试的核心是对抗性思维：找到输入点→追踪到达什么操作→测试能否注入
  • 纵深防御：没有单层足够，但多层组合能大幅提高攻击成本
